# コードレビューと修正記録

確認日: 2026-11-14（JST）

現在の作業ツリー、認証・セッション・投稿API、管理画面、関連テストを照合した。前回からの未コミット変更は保持した。以下は再現条件を確認して修正した項目。

## P1: ログイン初期化中に認証情報がURLへ送信される

- 対象: `admin/dashboard/assets/login.js`、`login.html`、認証情報を扱うフォーム。
- 影響: 初期CSRF取得の完了までsubmitハンドラーが登録されず、その間の送信は既定のGETになる。パスワードがURLのクエリーに含まれ、履歴やアクセスログへ残り得る。JavaScriptが読み込まれない場合も同様。
- 修正: 初期取得を待たずにハンドラーを登録し、送信時にCSRFを取得する。認証情報を扱うHTMLフォームには明示的なPOSTと送信先を設定。サーバー側の認証・CSRF検証も維持する。

## P2: 古い編集画面から他者の保存内容を上書きできる

- 対象: `backend/src/server.js`、`backend/migrations/004_update_revisions.sql`、`admin/dashboard/assets/update-create.js`。
- 影響: 同じ投稿を2タブで開き、一方が保存した後にもう一方を保存すると、既存のリクエスト内の競合検知では古い本文を拒否できない。
- 修正: 投稿の整数`revision`と編集PATCHの`X-Update-Revision`を導入。版の不一致は保存せず`409`を返す。本文と公開状態の更新で版を進め、日時のミリ秒が一致しても競合を識別する。旧APIのヘッダー省略は互換性のため許容する。既存DBのデータを保持する移行も検証。
- 添付削除後は添付表示のみを更新し、編集中の本文と元の版番号を保持。他者の最新版を読み込んだことにして古い本文を保存する経路も防止。

## P2: 日本語の添付ファイル名が文字化けする

- 対象: `backend/src/update-files.js`。
- 影響: multipartのファイル名が既定のlatin1で解釈され、日本語名が保存時・ダウンロード時に壊れる。
- 修正: ファイル名パラメーターをUTF-8で処理する。日本語の`originalName`とダウンロードの`Content-Disposition`をAPIで検証。

## P2: 保存中の追加入力が消える

- 対象: `admin/dashboard/assets/account.js`、`admins.js`。
- 影響: プロフィール・管理者作成・管理者編集は送信ボタンだけを無効化していたため、保存要求後に入力した内容が成功時の再描画・resetで失われる。プロフィールの初期取得も入力と競合していた。
- 修正: 初期取得前と保存中に対象フォーム全体を操作不可にし、CSRF取得前に送信内容を取得。再入を防ぎ、失敗時は入力を保持して操作を再開。プロフィールは保存APIの結果を表示し、追加GETによる上書きや誤った保存失敗表示を避ける。初期取得失敗時の再試行も追加。

## P2: 管理者一覧の応答順序によって同じ行が重複する

- 対象: `admin/dashboard/assets/admins.js`。
- 影響: 作成済みの管理者が一覧取得に先に含まれ、その後作成POSTの応答が届くと、同じIDの行が2つ表示される。
- 修正: GET・POST双方の行追加でIDの重複を防止し、すでに表示された行の未保存入力を保持。両方の応答順を検証。

## P2: 編集の再試行後に古い予約状態が表示される

- 対象: `admin/dashboard/assets/update-create.js`。
- 影響: 初期取得が一部だけ成功した後に再試行すると、公開取り下げ済みでも予約欄が非表示のまま、または予約解除済みでも古い日時が残る。
- 修正: 投稿読み込みのたびに予約欄の表示状態と日時を明示的に設定。
