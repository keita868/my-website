# Webサイト管理システム（CMS）構成案

更新日：2026-11-09

## 1. プロジェクトの方針

既存のHTML/CSS/JavaScriptによる公開サイトを維持しながら、独立した管理画面とバックエンドを追加する。

管理画面では、固定ページと記事の両方を編集できるようにする。文章や画像を組み合わせるブロック編集と、必要に応じたHTML編集の両方を想定する。

現時点では未公開。Gitでソースコードを管理している。

## 2. 全体構成

``` text
ブラウザ
  ├── 公開サイト（HTML/CSS/JavaScript）
  └── 管理画面（HTML/CSS/JavaScript）
          │
          ▼
      バックエンド API
      （Node.js + Express）
          │
          ├── 認証・セッション管理
          ├── 固定ページ管理
          ├── 記事・カテゴリ管理
          ├── メディア管理
          ├── サイト設定
          └── 操作履歴
          │
          ▼
      データベース（開発時はSQLiteを候補）
          ＋
      画像・ファイルストレージ
```

管理画面から直接HTMLファイルを書き換えるのではなく、API経由でデータベースにコンテンツを保存する。公開サイトは公開済みデータを取得して表示する。

## 3. 管理画面のページ構成

  -----------------------------------------------------------------------------------------------
  URL案                        画面                    主な機能
  ---------------------------- ----------------------- ------------------------------------------
  `/admin/login`               ログイン                管理者認証

  `/admin`                     ダッシュボード          公開ページ数、下書き数、最近の更新

  `/admin/pages`               固定ページ一覧          一覧、検索、新規作成

  `/admin/pages/new`           固定ページ作成          ブロック編集、HTML編集、プレビュー

  `/admin/pages/:id/edit`      固定ページ編集          内容・公開状態の変更

  `/admin/articles`            記事一覧                一覧、検索、カテゴリ確認

  `/admin/articles/new`        記事作成                タイトル、本文、画像、カテゴリ、公開設定

  `/admin/articles/:id/edit`   記事編集                記事内容の変更

  `/admin/categories`          カテゴリ管理            カテゴリの追加・編集・削除

  `/admin/media`               メディア管理            画像アップロード、一覧、削除

  `/admin/settings`            サイト設定              サイト名、説明、OGP、SNSリンク等

  `/admin/security`            セキュリティ            セッション確認、MFA等

  `/admin/logs`                操作履歴                ログイン、編集、公開、削除の記録
  -----------------------------------------------------------------------------------------------

## 4. 編集機能

### 固定ページ

-   タイトル
-   URLスラッグ
-   ブロック形式の本文
-   HTML編集モード（必要に応じて）
-   公開・下書き状態
-   プレビュー
-   更新履歴

想定するブロック：

-   見出し
-   段落
-   画像
-   リンク
-   リスト
-   ボタン
-   区切り線

### 記事

-   タイトル
-   URLスラッグ
-   本文
-   サムネイル
-   カテゴリ・タグ
-   下書き・公開・予約状態
-   公開日時・更新日時
-   プレビュー
-   更新履歴

### メディア

画像ファイル本体はファイルストレージに保存し、DBにはファイル名、保存先、MIMEタイプ、サイズなどのメタデータを保存する。

アップロード時はファイルサイズ、実際のファイル形式、画像の内容などを検証する。アップロードしたファイルをサーバー上で実行できる場所に置かない。

## 5. 推奨技術（暫定）

  領域           技術候補                  用途
  -------------- ------------------------- ----------------------------
  公開サイト     HTML / CSS / JavaScript   公開ページの表示
  管理画面       HTML / CSS / JavaScript   CMSの操作画面
  バックエンド   Node.js + Express         API、認証、公開処理
  開発用DB       SQLite                    小規模な開発・運用
  将来のDB候補   PostgreSQL                複数人利用や運用規模拡大時
  パスワード     Argon2id                  パスワードハッシュ化
  セッション     サーバー側セッション      ログイン状態の管理

この技術選定は暫定。実際のホスティング先や運用人数を決めた段階で最終決定する。

## 7. データベース設計案

  テーブル       主な役割
  -------------- --------------------------------------------------
  `admins`       管理者アカウント
  `pages`        固定ページ
  `articles`     記事
  `categories`   記事カテゴリ
  `media`        画像・ファイルのメタデータ
  `revisions`    ページ・記事の編集履歴
  `settings`     サイト設定
  `sessions`     ログインセッション（セッションストアを使う場合）
  `audit_logs`   管理者の操作履歴

ページ・記事の本文は、ブロックエディタのデータをJSONとして保存する案を採用する。JSONの形式にはバージョンを持たせ、将来のエディタ変更に備える。

## 8. Gitとデータベースの管理方針

**Gitで管理するもの**

-   アプリケーションのソースコード
-   SQLマイグレーション（テーブル作成・変更履歴）
-   再現可能な開発用シードデータ
-   `.env.example`（値はダミー）
-   README、設計資料

**原則Gitに入れないもの**

-   実際に使用するSQLite DBファイル
-   `.env` などの秘密情報
-   管理者のパスワードやセッショントークン
-   本番のアップロード画像
-   DBや画像のバックアップ

SQLiteを使う場合の例：

``` text
backend/
├── data/
│   └── cms.sqlite       # Git管理対象外
└── uploads/             # Git管理対象外
```

`.gitignore` の例：

``` gitignore
# Secrets
.env
.env.*
!.env.example

# Database
*.sqlite
*.sqlite3
*.db

# Uploaded files and backups
backend/uploads/
backups/

# Dependencies
node_modules/
```

### DBの変更方法

DBの構造変更は、手作業で本番DBを編集するのではなく、マイグレーションファイルで管理する。

例：

``` text
database/
└── migrations/
    ├── 001_create_admins.sql
    ├── 002_create_pages.sql
    ├── 003_create_articles.sql
    └── 004_create_media.sql
```

マイグレーションはGitにコミットする。各環境で適用済みのマイグレーションを記録し、同じ変更を二重適用しないようにする。

### バックアップ

SQLiteのDBファイルを単純コピーするだけでなく、SQLiteのバックアップ機能や
`.backup`
コマンドなど整合性を保てる方法を使う。DBとアップロードファイルの両方をバックアップし、復元テストも行う。

## 9. セキュリティ方針

-   管理者アカウントは一般ユーザー登録と分離する。
-   初期管理者は安全な初期セットアップ手順で作成する。
-   パスワードはArgon2id等でハッシュ化する。
-   セッションIDはログイン時に再生成し、ログアウト・期限切れ時に失効させる。
-   CookieはHTTPS環境で`Secure`、`HttpOnly`、適切な`SameSite`を設定する。
-   管理APIはすべてサーバー側で認証・認可する。
-   Cookie認証を使う更新系APIにはCSRF対策を行う。
-   ログイン試行をレート制限する。
-   SQLはプレースホルダーを使う。
-   HTMLは表示前に許可リスト方式などでサニタイズする。
-   アップロードファイルの形式・サイズを検証し、実行可能な場所に保存しない。
-   秘密情報をGitや操作ログに含めない。
-   HTTPS、定期バックアップ、依存パッケージの更新を行う。

## 10. 実装順序

1.  既存サイトのファイル構成・公開方法を確認する。
2.  バックエンドとDBの初期セットアップを行う。
3.  マイグレーションと初期管理者作成を実装する。
4.  管理者ログイン、セッション、CSRF等の認証基盤を作る。
5.  管理画面の共通レイアウトを作る。
6.  固定ページの一覧・作成・編集・下書き・プレビューを実装する。
7.  記事・カテゴリ管理を実装する。
8.  メディア管理を実装する。
9.  公開サイトから公開コンテンツを表示する仕組みを作る。
10. 編集履歴、操作ログ、バックアップ、セキュリティテストを追加する。
