## 👥 開発メンバー向け 運用・開発ガイドライン

### 1. 日常ワークフロー & 注意事項

| 項目 / ステップ | 操作 / コマンド / ルール | 内容説明 | 注意事項・禁忌事項 |
| :--- | :--- | :--- | :--- |
| **事前準備** | `git checkout main`<br>`git pull origin main` | 作業開始前に最新の `main` をローカルに取り込む | 古い `main` からブランチを切るとコンフリクトの原因になるため必ず実行すること |
| **ブランチ作成** | `git checkout -b feature/機能名` | 機能追加や修正ごとに専用ブランチを作成する | **`main` ブランチでの直接開発・コミットは絶対禁止** |
| **作業・コミット** | `git add .`<br>`git commit -m "種別: 変更内容"` | 適切な粒度で変更を記録する | 意味不明なメッセージ（`git commit -m "a"` など）は不可<br>未コミット状態でのブランチ切り替えは作業消失の危険あり |
| **ブランチ送信** | `git push origin feature/機能名` | 作成した作業ブランチを GitHub へ送信する | **`git push -f`（強制プッシュ）は履歴を壊すため絶対に使用しないこと** |
| **プルリク作成** | GitHub上で **「Compare & pull request」** | 変更点とテスト結果を明記して PR を送信する | レビューなしでの自己マージは禁止 |
| **レビュー・統合** | レビュアーが内容確認後 **「Merge pull request」** | 問題がなければ `main` ブランチへマージする | コンフリクトが発生している場合は作成者がローカルで解消すること |
| **環境同期** | `git checkout main`<br>`git pull origin main` | マージ完了後、ローカルの `main` を最新化する | マージ済みの作業用ブランチはローカル・GitHubともに削除すること |

### 2. 禁止事項・セキュリティ注意事項一覧

| 禁止行為 | なぜ禁止か・リスク | 正しい対処法 |
| :--- | :--- | :--- |
| **`main` ブランチへの直接 push** | テスト未完了のコードが混入し、全体の本番環境や他メンバーの作業を破壊するため | 必ず `feature/機能名` ブランチを作成し、プルリクエスト経由でマージする |
| **機密情報・パスワードのコミット** | APIキーや個人情報が GitHub 上に公開され、不正利用のリスクが生じるため | `.gitignore` に対象ファイル（`.env` 等）を記述し、リポジトリから除外する |
| **ビルド生成物の直接修正** | `js/main.js` 等を手修正しても、コンパイル時に上書きされて変更が消えるため | 必ず `src/ts/` 以下の TypeScript ソースコードを編集してコンパイルする |
| **巨大なバイナリファイルのコミット** | リポジトリの容量が肥大化し、`git clone` や `push` が極端に重くなるため | 大容量画像や動画、不要なライブラリ群は Git 管理外にするか LFS を検討する |
